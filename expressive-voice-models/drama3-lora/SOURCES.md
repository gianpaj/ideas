## Metadata verification

Ran [inspect_checkpoint.py](inspect_checkpoint.py) with all three pinned checkpoint IDs, using the Hub index and HTTP 206 range responses for the safetensors header length and header JSON. The script checks shard/index membership and reports tensor bytes by namespace and dtype. It caps header and index reads. A simulated HTTP 200 response was rejected before the script read its body. It does not load tensor values.

| Launch `dd64a85…`      |      8 |         8,678,728 |                 39,594,895,616 |       62,245 |
| Replacement `78e5ab7…` |     15 |         8,655,752 |                 39,594,895,616 |       62,245 |
| Japanese `e3762fe…`    |      8 |         8,678,664 |                 39,594,895,616 |       62,245 |

All three index key sets match. Each header aggregate reports 32,212,254,720 FP8 bytes, 7,864,320 FP32 bytes, and 7,374,776,576 BF16 bytes. The config values match across all three (trailing newline difference for the replacement). SHA-256 matches across all three for `tokenizer.json`, `tokenizer_config.json`, `special_tokens_map.json` and `chat_template.jinja`. All three codec LFS records list 1,871,099,728 bytes and SHA-256 `74fc41c5a7151c6f350af8bd7e5d6e3accfcc7f3dfbfac23afd35af07052bb2f`. This is server metadata, rather than a local hash of a full download. [Launch metadata](https://huggingface.co/api/models/fishaudio/drama-3/revision/dd64a85cd82e9521f7202610ede97b367fc83946?blobs=true) · [Replacement metadata](https://huggingface.co/api/models/fishaudio/drama-3/revision/78e5ab79e49aa9a25abe8799eff2c4d73a1c3216?blobs=true) · [Japanese metadata](https://huggingface.co/api/models/Aratako/Drama-3-Japanese/revision/e3762febfc794eaa1d08ee9931215365f92968a8?blobs=true)

Selected header shapes confirm the separate token table and LM head `[252288,2048]`, per-expert gate/up `[512,2048]` and down `[2048,512]` with FP32 scale grids `[4,16]` and `[16,4]`, and the first residual head `[4096,2048]`. A second inspector run verified BF16 `[2048,4096]` weights at each of the four proposed LoRA sites in layers 36–39.

A separate probe compared SHA-256 of the first 4,096 payload bytes of 15 named tensors per revision (180 KiB total), using the same strict range reader. Reproduce by looking up the shard and `data_offsets[0]` in its header, then request the range starting at `8 + header_length + data_offsets[0]`. This detects differences independent of sharding, without reading full tensors.

For automatic annotation, use an event detector or event-aware ASR to nominate clips, align events to the adjacent words, and have a listener confirm the event and its source. Save onset and offset before trimming. General speech recognition alone often drops these sounds. A published detector reports modest held-out precision and recall, so treat detector results as candidates. Use NoVA's public prompts or NVV-SuperBench for held-out tests. ## Verification boundary

Executed source and metadata checks, read-only system telemetry, and FFmpeg normalization on a generated stereo fixture. Native CLI options and the training interface were inspected statically. The PyTorch graph, training losses, inference fidelity, memory peaks and speed were not run locally. Publisher performance numbers are attributed to their workloads. The adapter budget and projected training memory are calculations. No full checkpoint, model runtime environment or audio dataset was downloaded for this study.
